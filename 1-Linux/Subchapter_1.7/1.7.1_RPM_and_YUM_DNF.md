## 1.7.1 RPM, YUM, and DNF: Recognition Notes for Ubuntu-Focused Learners

#### Why This Note Is Short

This course is Ubuntu-first. Most hands-on package-management practice should happen in [1.7.2 DPKG and APT](./1.7.2_DPKG_and_APT.md). Still, platform engineers occasionally inherit RPM-based servers, vendor appliances, or enterprise images, so you should recognize the vocabulary without memorizing a parallel command set.

***

## The Mental Model

| Concept | Ubuntu/Debian world | RPM-based world |
| --- | --- | --- |
| Package file | `.deb` | `.rpm` |
| Low-level package database | `dpkg` | `rpm` |
| High-level package manager | `apt` | `dnf` or older `yum` |
| Repository metadata | APT sources | YUM/DNF repo files |

`rpm` is the low-level package format and database tool. `dnf` is the modern high-level manager that resolves dependencies and talks to repositories. `yum` is the older high-level tool still seen on legacy systems.

For your day-to-day learning path, use `apt`. Use the RPM terms only to identify a non-Ubuntu host and choose the right runbook.

***

## Minimal Recognition Commands

These are the only RPM-family commands worth keeping in this Ubuntu-focused module:

```bash
# Identify the operating system before choosing package commands
cat /etc/os-release

# If you are on an RPM-based host and must inspect ownership of a file
rpm -qf /path/to/file

# If you are on an RPM-based host and must list installed packages
rpm -qa | head
```

Do not blindly translate Ubuntu commands into RPM commands during production work. Check the vendor runbook, image build docs, or team standard first.

***

## When You Actually Need RPM/DNF Knowledge

- You are debugging a vendor appliance or enterprise VM image that is not Ubuntu.
- A package install failed in CI because the base image is Fedora, Rocky, Alma, or RHEL.
- A security team gives you an RPM package inventory and asks whether a library is installed.
- You are reading documentation that only ships RPM installation instructions.

If none of those apply, continue with Ubuntu APT.

***

## Quick Task: Identify the Package Family

1. Run `cat /etc/os-release`.
2. Identify whether the machine is Ubuntu/Debian-based or RPM-based.
3. State which package-management note you should use next.

> **Ready Solution:**
>
> ```bash
> cat /etc/os-release
> ```
>
> If `ID=ubuntu` or `ID_LIKE=debian`, continue to [1.7.2 DPKG and APT](./1.7.2_DPKG_and_APT.md). If the host is RPM-based, use this note only for recognition and then follow the approved runbook for that environment.

***

## Summary

- This course is Ubuntu-first, so `apt` and `dpkg` are the primary package-management tools.
- RPM-based systems use `.rpm` packages, the `rpm` database, and usually `dnf` as the high-level manager.
- Keep RPM knowledge lightweight unless your real environment requires it.
- Always inspect `/etc/os-release` before running package commands on an unfamiliar host.
